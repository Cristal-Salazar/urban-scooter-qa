# Lista de comprobación | Estado de pedidos

**Proyecto:** Urban Scooter  
**Tipo de prueba:** Pruebas funcionales web  
**Artefacto:** Lista de comprobación

## Objetivo

Verificar que el usuario pueda consultar el estado de un pedido y visualizar correctamente la información correspondiente.

## Ejemplos de comprobaciones ejecutadas

| ID | Comprobación | Resultado |
|---|---|---|
| 1 | Al seleccionar «Estado del pedido» desde el encabezado, se muestra el campo «Número de pedido». | APROBADO |
| 2 | El usuario puede introducir un número de pedido en el campo correspondiente. | APROBADO |
| 3 | Al introducir un número de pedido válido y presionar Enter, se muestra la información del pedido. | APROBADO |
| 4 | Al introducir un número de pedido inválido, aparece el mensaje correspondiente. | APROBADO |
| 5 | El usuario puede introducir otro número de pedido y consultar un estado diferente. | APROBADO |
| 6 | Se muestran los datos del pedido. | APROBADO |
| 7 | El texto pasa a una segunda línea cuando no cabe en una sola. | APROBADO |
| 8 | Solo un estado del pedido puede estar activo al mismo tiempo. | APROBADO |
| 9 | El estado actual aparece resaltado en color negro. | APROBADO |

## Técnicas y habilidades demostradas

- Análisis de requisitos funcionales.
- Diseño de listas de comprobación.
- Validación de entradas válidas e inválidas.
- Verificación de elementos de interfaz.
- Registro de resultados de ejecución.

Selección de comprobaciones documentadas en la hoja de pruebas web del proyecto final de QA Engineer de TripleTen.
